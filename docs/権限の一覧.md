# 権限の一覧（だれが・何を見られるか／どこで判定しているか）

2026-11 の依頼3で、見える範囲を直す前に「今の権限の判定がどこにあるか」をまとめたものです。
直したところは **（2026-11で変更）** と書いています。ロールの呼び名は CLAUDE.md に合わせています。

## しくみ（3つの層）

| 層 | 何をしているか |
|---|---|
| 画面（サーバーで描く画面） | `requireSession()`（ログイン必須）／`requireAdmin()`（管理者のみ）／`isExecutive()`（幹部・管理者）でページの最初に判定し、見られない人は別の画面へ戻す。メニュー（`src/lib/nav.ts`）とホームのメニューでも出し分ける |
| API・サーバーアクション | 画面と同じ判定を、保存・送信の処理の中でもう一度行う（URLやフォームを直接たたいても通らない） |
| DB（Supabase） | すべてのテーブルでRLSを有効にし、ポリシーは作らない。anon・authenticated キーからは一切読めず、サーバーのサービスロールだけが読み書きする。ユーザーごとの見える範囲は上の2つで判定する（Supabase Auth を使わない自前ログインのため、ユーザー単位のRLSは使えない） |

判定の部品は `src/lib/auth/session.ts`（ログイン・管理者）、`src/lib/eni/access.ts`（幹部・議事録・会議体・組織図）、`src/lib/chat.ts`（トーク）、`src/lib/ai-shimon/access.ts`（代表）、`src/lib/views.ts`（閲覧状況）にあります。

## ロールの判定

| 呼び名 | コード上の判定 |
|---|---|
| 管理者 | `staff.role = 'admin'`（`session.role === "admin"`） |
| 店舗の管理者（岡さんなど） | **`staff.role = 'manager'` ＋ 担当店舗 `staff.managed_store_ids`（2026-11で追加）**。管理者画面には入れない |
| 幹部 | `staff.is_executive = true`。`isExecutive()` は管理者も含めて true |
| 代表 | `staff.is_owner = true`（AIしもんの相談の記録を読める。画面からは変えられない） |
| スタイリスト／アシスタント | `staff.job_type = 'stylist' / 'assistant'` |
| イーリスのスタッフ | 所属店舗（`staff.store_id`）の店舗名に「EREYS」が入っている人 |

## 2026-11 依頼10〜23（追加開発）

人ごとに付ける権限（ロールとは別）は `src/lib/permissions.ts` の `PERMISSION_DEFS`（管理画面 `/admin/permissions`）。
「代表だけ」の権限（AIしもんの相談の閲覧・教育・Claudeからの読み取り）は、代表本人だけが、代表にだけ付け外しできます（管理者でも自分には付けられない）。
新しいテーブルはすべて RLS を有効にし、ポリシーは作りません（上の「DB」の層と同じ）。
